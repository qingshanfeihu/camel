## 1. 问题诊断

### 根本原因
SiliconFlow API 的 **p99 延迟约 60.15 秒**，但网关超时设置仅为 **60.0 秒**，导致约 1% 的请求超时。

### 超时事件记录
| 时间 | Primary | 延迟 | Failover | 结果 |
|------|---------|------|----------|------|
| 21:43:38 | qwen3-8b_key2 | 60.15s | key1 | ✅ 成功 |
| 21:45:20 | qwen3-8b_key1 | 60.12s | key2 | ✅ 成功 |
| 21:46:20 | qwen3-8b_key1 | 60.15s | key2 也超时 | ❌ 失败 |

### 关键发现
- 所有超时都精确在 60.12-60.15s，是硬性超时触发而非网络波动
- 两个独立 API keys 同时超时，说明是上游 API 性能问题
- 原 60s 超时无法覆盖 SiliconFlow p99 延迟

## 5. 技术说明

### 为什么是 90s 而非 120s？
- 缓冲区: 90 - 60.15 = 29.85s，足以覆盖 p99 延迟
- 保持快速失败和稳定性的平衡

### 为什么禁用 SDK 重试 (max_retries=0)？
- OpenAI SDK 默认重试会导致 3x 延迟
- 网关已实现多键故障转移，无需 SDK 级重试
